# Testing Strategy (CodeZync POS)

You are acting as the senior Flutter architect deciding what to test first in a
codebase that currently has **no real tests** — `test/widget_test.dart` is still
the unmodified Flutter counter-app smoke test generated by `flutter create`.
Don't try to backfill 100% coverage. Build the muscle where it pays off fastest:
the logic-dense layers (repositories, use cases), not the glue.

## 0. Verify before assuming

Checked as of this writing: `pubspec.yaml` `dev_dependencies:` only has
`flutter_test` (SDK) and `flutter_lints: ^5.0.0`. **`mocktail`, `mockito`, and
`bloc_test` are NOT present.** Re-check `pubspec.yaml` before following this
skill — if someone has since added one of these, use what's already there
instead of adding a competing mocking library.

Add, matching this pubspec's `^x.y.z` pinning style:

```yaml
dev_dependencies:
  flutter_test:
    sdk: flutter
  flutter_lints: ^5.0.0
  mocktail: ^1.0.4
  bloc_test: ^10.0.0
```

Use **mocktail**, not mockito: this codebase is null-safe throughout and
mocktail needs no `build_runner`/codegen step (no `.mocks.dart` files to
regenerate), which fits a project with no existing codegen pipeline. `bloc_test`
is the standard companion to `flutter_bloc: ^9.0.0` (already a dependency) for
asserting emitted state sequences.

## 2. Use-case tests — mock the repository, assert pass-through + both branches

Use cases in this codebase (e.g. `lib/features/session/domain/usecase/add_cash_movement_usecase.dart`)
are thin: `implements UseCase<T, Params>` and just forward to the repository.
The test exists to lock in that contract, not to find bugs in trivial code —
keep it short.

```dart
// test/features/session/domain/usecase/add_cash_movement_usecase_test.dart
import 'package:codezync_pos/core/enums/movement_type.dart';
import 'package:codezync_pos/core/error/failure.dart';
import 'package:codezync_pos/features/session/domain/entities/cash_movement_entity.dart';
import 'package:codezync_pos/features/session/domain/params/add_cash_movements_params.dart';
import 'package:codezync_pos/features/session/domain/repository/session_repository.dart';
import 'package:codezync_pos/features/session/domain/usecase/add_cash_movement_usecase.dart';
import 'package:dartz/dartz.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';

class MockSessionRepository extends Mock implements SessionRepository {}

void main() {
  late MockSessionRepository repository;
  late AddCashMovementUseCase useCase;

  setUp(() {
    repository = MockSessionRepository();
    useCase = AddCashMovementUseCase(repository: repository);
  });

  final params = const AddCashMovementsParams(
    movementType: MovementType.cashIn,
    amount: 50,
    reason: 'Till top-up',
    sessionId: 'session-1',
  );

  test('returns Right with the repository result on success', () async {
    final movement = CashMovementEntity(
      id: 'm1',
      movementType: MovementType.cashIn,
      amount: 50,
      reason: 'Till top-up',
    );
    when(() => repository.addCashMovement(params: params))
        .thenAnswer((_) async => Right(movement));

    final result = await useCase(params);

    expect(result, Right(movement));
    verify(() => repository.addCashMovement(params: params)).called(1);
  });

  test('returns Left when the repository fails', () async {
    when(() => repository.addCashMovement(params: params))
        .thenAnswer((_) async => const Left(UnknownFailure('boom')));

    final result = await useCase(params);

    expect(result, const Left(UnknownFailure('boom')));
  });
}
```

Note: `CashMovementEntity`/`MovementType` constructor fields above are
illustrative of the shape — check `lib/features/session/domain/entities/cash_movement_entity.dart`
and `lib/core/enums/movement_type.dart` for the exact fields before copying
this verbatim. Because entities extend `Equatable`, `expect(result, Right(movement))`
works on value equality, not identity — no need for a custom matcher.

## 3. Repository-impl tests — this is where the real logic lives, test it precisely

`SessionRepositoryImpl` (`lib/features/session/data/repository/session_repository_impl.dart`)
is the highest-value test target in the codebase: `getSession()` alone branches
on **string-matching the caught error's message** (not on typed exception
classes) to decide between "no active session" vs "offline, fall back to
cache" vs "unknown failure". That string-matching is exactly the kind of logic
that silently breaks when someone tweaks an error message upstream — pin it
down with a test per branch:

```dart
// test/features/session/data/repository/session_repository_impl_test.dart
import 'package:codezync_pos/core/error/failure.dart';
import 'package:codezync_pos/features/session/data/datasource/session_local_datasource.dart';
import 'package:codezync_pos/features/session/data/datasource/session_remote_datasource.dart';
import 'package:codezync_pos/features/session/data/model/session_model.dart';
import 'package:codezync_pos/features/session/data/repository/session_repository_impl.dart';
import 'package:dartz/dartz.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';

class MockRemote extends Mock implements SessionRemoteDatasource {}
class MockLocal extends Mock implements SessionLocalDatasource {}

void main() {
  late MockRemote remote;
  late MockLocal local;
  late SessionRepositoryImpl repository;

  setUp(() {
    remote = MockRemote();
    local = MockLocal();
    repository = SessionRepositoryImpl(datasource: remote, localDatasource: local);
  });

  group('getSession', () {
    test('caches and returns Right on success', () async {
      final model = SessionModel.fromJson(_validSessionJson);
      when(() => remote.getSession()).thenAnswer((_) async => model);
      when(() => local.saveSession(model)).thenAnswer((_) async {});

      final result = await repository.getSession();

      expect(result, Right(model));
      verify(() => local.saveSession(model)).called(1);
    });

    test('clears cache and returns NotFoundFailure when server has no active session', () async {
      when(() => remote.getSession()).thenThrow(Exception('No active session'));
      when(() => local.deleteSession()).thenAnswer((_) async {});

      final result = await repository.getSession();

      expect(result, const Left(NotFoundFailure('No active session')));
      verify(() => local.deleteSession()).called(1);
    });

    test('falls back to cached session on a network-shaped error', () async {
      final cached = SessionModel.fromJson(_validSessionJson);
      when(() => remote.getSession()).thenThrow(Exception('SocketException: failed'));
      when(() => local.getSession()).thenAnswer((_) async => cached);

      final result = await repository.getSession();

      expect(result, Right(cached));
    });

    test('returns UnknownFailure when offline and nothing is cached', () async {
      when(() => remote.getSession()).thenThrow(Exception('SocketException: failed'));
      when(() => local.getSession()).thenAnswer((_) async => null);

      final result = await repository.getSession();

      expect(result, isA<Left<Failure, dynamic>>());
    });
  });
}

const _validSessionJson = {
  // fill in the real shape from session_model.dart's fromJson
};
```

This test suite is what would have caught, for example, a rename of the "no
active session" substring breaking the offline/no-session branch split. When
you touch a repository impl with branching like this, write the test *before*
refactoring the branching logic, not after.

## 4. BLoC tests — `blocTest`, mock the use cases, assert the state sequence

```dart
// test/features/session/presentation/bloc/session_bloc_test.dart
import 'package:bloc_test/bloc_test.dart';
import 'package:codezync_pos/core/error/failure.dart';
import 'package:codezync_pos/core/usecase/usecase.dart';
import 'package:codezync_pos/features/session/domain/usecase/get_session_usecase.dart';
import 'package:codezync_pos/features/session/presentation/bloc/session_bloc.dart';
import 'package:codezync_pos/features/session/presentation/bloc/session_event.dart';
import 'package:codezync_pos/features/session/presentation/bloc/session_state.dart';
import 'package:dartz/dartz.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';

class MockGetSessionUseCase extends Mock implements GetSessionUseCase {}
// ...mock the bloc's other 5 required use cases the same way

void main() {
  late MockGetSessionUseCase getSessionUseCase;

  setUp(() {
    getSessionUseCase = MockGetSessionUseCase();
  });

  blocTest<SessionBloc, SessionState>(
    'emits [SessionLoading, SessionLoaded] when GetSessionEvent succeeds',
    build: () {
      when(() => getSessionUseCase(const NoParams()))
          .thenAnswer((_) async => Right(fakeSessionEntity));
      return SessionBloc(
        getSessionUseCase: getSessionUseCase,
        openSessionUseCase: /* mock */,
        getSessionByIdUsCase: /* mock */,
        getCashMovementsUseCase: /* mock */,
        addCashMovementUseCase: /* mock */,
        closeSessionUseCase: /* mock */,
      );
    },
    act: (bloc) => bloc.add(const GetSessionEvent()),
    expect: () => [
      const SessionLoading(),
      SessionLoaded(entity: fakeSessionEntity, movements: fakeSessionEntity.cashMovements),
    ],
  );

  blocTest<SessionBloc, SessionState>(
    'emits [SessionLoading, NoActiveSession] when the failure message says so',
    build: () {
      when(() => getSessionUseCase(const NoParams())).thenAnswer(
        (_) async => const Left(NotFoundFailure('No active session')),
      );
      return SessionBloc(getSessionUseCase: getSessionUseCase, /* ...other mocks */);
    },
    act: (bloc) => bloc.add(const GetSessionEvent()),
    expect: () => [const SessionLoading(), const NoActiveSession()],
  );
}
```

`SessionBloc` requires all six use cases in its constructor even when a test
only exercises one event — mock every one of them (a `Mock`-generated stub
that's never `when()`-stubbed will throw if accidentally invoked, which is
useful: it catches a test wiring the wrong event to the wrong use case).

## 5. Priority order given zero starting coverage

1. **Repository implementations** — highest logic density (exception→Failure
   mapping, offline fallback branching, cache invalidation side effects),
   cheapest to test (two mocked datasources, no widget tree).
2. **Use cases that aren't pure pass-through** — if a use case ever grows
   beyond `return repository.x(params)` (orchestrates multiple repository
   calls, does validation), test it. Pure pass-through use cases are optional
   (see below).
3. **BLoCs** — one `blocTest` per event covering the success path and the
   distinct failure branches the handler actually implements (e.g.
   `SessionBloc`'s `NoActiveSession` vs generic `SessionFailure` split).
4. **Widgets/pages** — last, and only for screens with real conditional
   rendering (e.g. a dialog that shows different content per BLoC state).
   Don't write widget tests that just assert `CustomTextPoppins` rendered a
   static string.

## 6. What NOT to bother testing right now

- Plain `Equatable` entities/models — no logic, `props` is self-verifying.
- Pure pass-through use cases (the vast majority — see
  `flutter-clear-architecture` §5) unless you're touching that specific file
  for another reason and want a cheap regression net.
- `dependency_injection.dart` wiring — there's no useful assertion beyond "it
  compiles and doesn't throw at `init()`", which `flutter analyze` plus
  actually running the app already covers.
- Legacy ad-hoc-pattern features (e.g. `cashier`'s `CashierListUsecase`/
  `CashierFailureEntity`) — don't invest test time in a pattern that's meant to
  be migrated away from; migrate it to the modern `UseCase<T, Params>` pattern
  first (per `flutter-clear-architecture`), *then* test the migrated version.

## 7. Checklist

- [ ] `mocktail` and `bloc_test` added to `pubspec.yaml` `dev_dependencies` (once, not per-PR) if still absent — verify first.
- [ ] New test file's path mirrors the `lib/features/<feature>/` path being tested.
- [ ] Repository-impl test covers every distinct branch in its `catch` block, not just the happy path.
- [ ] BLoC test uses `blocTest` and asserts the full emitted state list, including intermediate `Loading` states.
- [ ] No test added for trivial Equatable entities/pass-through use cases/DI wiring.
